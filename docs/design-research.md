# 設計研究：台灣空品監測重設計

2026-10-22。目的：在重做介面前，先看同類產品怎麼處理「現在空氣如何」「哪裡比較差」「資料多新」三件事，學框架與 UI/UX，而不是憑感覺排版。

> 標記說明：✅ 本輪實際開頁或查官方文件確認；◐ 依產品公開介面與既有經驗整理，本輪未逐項重新驗證。

## 2. 共同模式

1. **先回答「我這裡」，再談全台。** AirNow、IQAir 與天氣 App 都把所在地的大數字卡片放在最上方，地圖和排行放在後面。
2. **數字＋類別文字＋顏色三者並陳。** AirNow 從不只用顏色表達；aqicn 的標記本身就寫著數字。這也是色盲友善的關鍵：顏色只是輔助，資訊不靠顏色傳達。
3. **在色階條上標出目前位置。** Apple 天氣和 AirNow 都用一條六段色階條，讓人一眼看出「離下一級還有多遠」。
4. **地圖標記直接顯示數字。** aqicn 的做法比只畫顏色圓點更好掃讀，也更友善色盲使用者。
5. **時效要有時區、要能察覺過期。** IQAir 的「15:36, Oct 22」沒有年份與時區，是反例。PurpleAir 會把離線感測器變灰，是好例子。
6. **手機以單欄卡片為主，地圖與列表可以切換。** 大多數產品在手機上不會同時塞地圖與表格。

## 3. 本專案的現況問題（改版前）

- 三欄並排（選站表單、示意地圖、說明卡），手機上要捲很久才看到結果。
- 地圖是手繪的台灣輪廓，只放 12 個代表站，座標也經過壓縮，無法用來找測站。
- 沒有深色模式；AQI 顏色是壓暗的版本（例如普通用 #b77900），和官方「黃色」的認知落差大。
- 選站要先選縣市再選測站，不能用站名直接搜尋，也不會記住上次選的測站。
- 過期警示散落在三四個地方，文字重複。
- 部署面：production 實際上是從另一條分支 `codex/unified-visual-refresh` 建置，main 只放已退役的舊版前端；每小時的 cache 機器人 commit 讓歷史幾乎都是 bot。

## 4. 採用什麼、為什麼

| 決定 | 採用 | 為什麼 |
|---|---|---|
| 版面 | **「我的測站」大卡片 → 全台地圖＋測站列表 → 概況（分布、縣市排行）**，手機單欄；桌面把地圖與列表左右並排 | 學 AirNow 與 IQAir 先回答「我這裡」，同時保留原本「不預設全台最差站、不猜你在哪」的可信度原則 |
| 選站 | **一個搜尋框**，可輸入站名或縣市，下拉提示；記住上次選的測站（存在 localStorage） | 學環境即時通的收藏概念；比兩層下拉少一步 |
| 地圖 | **Leaflet＋CARTO 底圖**（淺色用 Positron、深色用 Dark Matter），所有測站都畫上去；標記是 aqicn 式的**數字膠囊** | Leaflet 輕量（約 40 KB gzip），不需要 API key，完全可以靜態部署在 GitHub Pages；數字標記比色點更好掃讀，也不靠顏色 |
| 色階 | **官方六級色相**（綠、黃、橘、紅、紫、褐紅），色值採 EPA／AirNow 標準色並微調亮度；淺色底的標記用深色字、深色底用白字 | 台灣使用者熟悉的是官方色相，原本壓暗的黃色會被誤讀成橘色。紅綠兩色的明度差很大，加上一定附數字與類別文字，色盲使用者也能分辨 |
| 色階條 | 卡片內放一條六段色階條＋目前位置指標，並標出 50／100／150／200／300 分界 | Apple 天氣與 AirNow 的做法，一眼看出「離下一級多遠」 |
| 過期處理 | **只在頁首放一個時效狀態**（綠點「X 分鐘前發布」／琥珀色「資料已過期 X 小時」），過期測站在地圖上以灰色虛線外框表示，卡片不提供活動建議 | 學 PurpleAir 的灰化；保留原本經過測試的 freshness 邏輯（3 小時門檻、未來時間戳），但把重複警示收斂成一處 |
| 深淺色 | 跟隨系統，並提供手動切換（記在 localStorage） | 晚上查空品很常見；地圖底圖同步切換 |
| 圖表 | 拿掉 Recharts，分布圖改用一條 CSS 堆疊長條，縣市排行改用簡單的長條清單 | 原本的圖表只有一張類別長條，用 Recharts 太重；拿掉後 bundle 少約 100 KB gzip |
| 前端框架 | 沿用 **Vite＋React 19＋TypeScript＋Tailwind** | 已有完整的資料正規化與測試（aqi.ts、cache contract）；換框架只會增加風險 |
| 資料與部署 | **main 成為唯一來源**；單一 Pages workflow 在 push main 與排程時用 Actions secret 在伺服器端抓 MOENV 資料，產生 `data/aqi-latest.json` 後才 build，**資料不再 commit 回 repo** | API key 永遠不進前端 bundle；不再產生每小時的 bot commit；抓取或驗證失敗時不部署，線上維持上一版（fail-closed） |

不採用：

- **Mapbox、Google Maps**：需要 token，違反「key 不進前端」原則。
- **主動定位**：原本的產品決策是不要求定位、也不宣稱「最近測站」，因為資料沒有站型與代表範圍。這次維持不變。
- **熱度圖內插**：測站稀疏時，內插出來的顏色會誤導使用者，所以只畫真實測站。
